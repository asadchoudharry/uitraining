# Skill-improvement proposals (PROPOSED — for owner review/import)

These are proposals to strengthen future enterprise-UI skills. Nothing here modifies any installed skill; the repository owner reviews and imports what earns its place. Each proposal is grounded in a corpus finding.

1. **Evidence-grading discipline** (`evidence-grading.md`) — every claim in a design study carries OBSERVED / CODE_VERIFIED / OFFICIALLY_DOCUMENTED / UI_VISIBLE_ONLY / INFERRED / PROPOSED / NOT_VERIFIED. Corpus lesson: S05's "workflow" pages look like automation but are CRUD records; S03 looks like a product but persists to localStorage only. A skill that cannot say "UI only" will fabricate backends.
2. **Interaction census before aesthetics** — enumerate controls/actions first (S03's 175-action table is the model), then critique visuals. Dashboards reviewed without a control census miss saved views, bulk actions and keyboard paths.
3. **Onboarding completeness checklist** — named steps, per-step save, data-reuse notes, value-proof step, integration step, invites last, stalled-account analytics (S09 + S03 + UIMG-030). Includes the anti-pattern list: pre-checked consent, unnamed progress bars, setup that restarts on plan change.
4. **Table-state battery** — flat/grouped, filters modal, scan/status strip, empty/error/permission states, page-size + export honesty (S10 tables; S05 CRUD tables).
5. **Token-first reconstruction** — derive observation tokens and a separate original semantic token set; never let the two mix (E10.1). Includes the S03 worked values (gutter rule, text ramp, color-mix derivatives) as a *pattern*, not as values to copy blindly.
6. **Rights gate in every research skill** — no LICENSE = no republication; portfolio art = analysis + metadata only; user-supplied images need explicit republication confirmation. The gate runs *before* any asset is committed, not in review.
7. **Review rubric** (`review-rubric.md`) — the QA gates used for this repository, reusable for future design-intelligence work.
