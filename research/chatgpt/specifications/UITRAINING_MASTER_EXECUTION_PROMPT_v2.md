## E02. Pixel-level visual forensic protocol

For every meaningful unique screen, route variation, design shot or provided image, create a **Screen Reconstruction Sheet (SRS)** with verifiable observations and uncertainty labels.

### E02.1 Capture matrix

- Record canonical URL, date/time, source version, page title, route, site theme and viewport dimensions.
- For accessible live websites, test desktop, tablet and mobile breakpoints as appropriate. Suggested representative widths: 320, 375, 390, 768, 1024, 1280, 1440 and 1920 px, but adapt to actual breakpoint behavior; do not produce redundant captures for unchanged states.
- Preserve viewport height, device pixel ratio, zoom, browser engine, OS/browser where known, font-loading status, color scheme, language, locale, motion preferences and scroll position.
- Capture the initial visible viewport AND a controlled full-page view where permission allows. Capture long-page segments with coordinates if sticky elements distort full-page results.
- Repeat captures for light/dark, RTL/LTR, compact/comfortable density, expanded/collapsed sidebar, full/mini navigation, and layout variants **only where those are actually available**.
- For each interactive view, capture normal, hover, focus-visible, active, selected, expanded, loading, empty, validation error, success, warning, destructive confirmation and disabled states where observable without destructive action.

### E10.3 Screenshot comparison and fidelity acceptance

When reference screenshots are legally available for comparison, take reproduction screenshots at the **same viewport, DPR, zoom, font-loading, theme, time/data fixture and interaction state**. Use side-by-side and overlay/diff images in the authorized working environment. Report measurements rather than unverified "100% pixel perfect" claims.

Evaluate:

- Shell geometry: sidebar, header, content bounding boxes, column distribution.
- Major card layout: size, padding, nesting, gaps, alignment, chart aspect ratios.
- Typography: font family and legally valid substitute, size, line height, weight, wrapping and truncation.
- Components: table density, modal bounds, controls, icon baselines, active states.
- Imagery: focal point, crop, aspect ratio and allowed replacements.
- State fidelity: menu open, collapsed navigation, form error, selected tab, loading and mobile states.

Record a measurement table of differences, e.g., bounding-box offset in px, size discrepancy in px or %, typography line breaks, key color differences, missing components and interaction mismatches. Set screen-specific acceptance tolerances before testing. Suggested initial thresholds for permitted licensed reproductions: major layout edge within 4 CSS px, major component size within 3%, zero missing primary regions, all priority controls wired, and no horizontal overflow at tested mobile widths. These are illustrative acceptance targets, not guaranteed visual similarity metrics. Tighten or relax only with a written reason. Do not use a magic percentage as proof of quality.

For clean-room originals, do NOT score distinctive expression against a copyrighted reference for exact visual identity. Instead validate adherence to abstract layout principles, information hierarchy, functionality, originality, usability and design-system consistency.
